# EVS3 E1 Deterministic Primitive Harness — local implementation

Status: test-only harness locally reviewed on 2026-09-22; E1 gate remains **BLOCKED / NOT EXECUTED**. See `EVS3_REVIEW_CLOSURE.md`.

The harness catalogs the 12 primitive families derived from `19_TEST_EVAL_ACCEPTANCE_PLAN.md` §7, seven boundary classes, exact expected structural outputs and three identical-input attempts per vector. It returns only case IDs, statuses and low-sensitivity reason codes. Stable mismatches yield `EVAL_HARD_ASSERTION_FAILED`; inconsistent attempts yield `EVAL_CASE_FLAKY`. Duplicate or non-synthetic vectors are rejected before execution. Vector functions must create fresh local state for every attempt.

Thirty-six synthetic vectors exercise Request Context/Tenant boundary, Subject/Identity resolution, Authorization precheck, Prohibition routing, stable Digest, Idempotency and Navigation State Transition, plus the five previously missing design-rule families. The idempotency key and replay classification logic were extracted from the synthetic executor into pure functions that the executor still calls. The additional EVS3-only pure functions cover policy-supplied Freshness limits, Evidence prerequisites, Ready candidate and revalidation triggers, explicit PHC class combination, configured Authority/SoD/Assurance conditions, field projection with unconditional sensitive-field exclusion, and synthetic Growth/Training/Eval partition and named contamination checks. The vectors include nominal and negative cases and all seven catalogued boundary classes. No business Capability, connector, channel, model or external sender is invoked by these vectors.

The local catalog now has nominal and negative vectors for all twelve families (`missingFamilies=[]`). This is **synthetic structural coverage, not formal E1 coverage or a runtime authorization claim**. The new policy primitives consume explicitly configured or preverified facts; they do not resolve customer-specific Freshness thresholds, real Authority grants, SoD policy, privacy release, data provenance, scanner implementation or production persistence. Missing policy, missing evidence or indeterminate contamination blocks. Idempotency vectors cover pure key/replay decisions, not concurrent persistence or production deduplication. The harness remains `BLOCKED` because there is no approved Suite/Dataset, frozen Subject, independent Oracle or Eval Run. None of these functions is bound to OpenClaw or the live Agent.

Run `corepack pnpm typecheck` and `corepack pnpm test`. `tests/e1-primitive-harness.test.ts` verifies the actual primitive vectors, repeated-input stability, mismatch/flaky classification and all-deny Eval Registry boundary. This implementation does not register an OpenClaw Tool or change the target agent routing.
